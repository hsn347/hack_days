## 3. سجل الأسباب الجذرية مصنفة حسب الأولوية (Root Cause Matrix)

### 🔴 أولوية حرجة جداً (Critical - P0)
1. **[SEC-P0-1] تسريب كلمات المرور بنص صريح في مسار `/api/local/castles/{identifier}` (`api_server.py:2767`)**:
   - **السبب الجذري:** غياب تبعية المصادقة `Depends(get_current_user)`، واستدعاء `get_castle` التي تعيد سطر الجدول كاملاً دون إزالة حقل `password` كما تفعل الدوال الأخرى.
2. **[SEC-P0-2] ثغرة انعدام التحقق من الملكية (BOLA/IDOR) في `/api/castle-data/{email}` (`api_server.py:2776`)**:
   - **السبب الجذري:** المسار يستقبل الإيميل من الرابط ولا يتحقق إطلاقاً من تبعية هذا الإيميل للمستخدم المسجل، ويقوم بفتح جلسة حية باللعبة وجلب البيانات.
3. **[SEC-P0-3] انتحال معاملات بدء البوت في `/api/bot/start` (`api_server.py:2590-2625`)**:
   - **السبب الجذري:** المسار يتحقق من ملكية `castle_id` لكنه يمرر `req.email` دون مطابقة، مما يسمح بتشغيل البوت باستخدام جلسة مستخدم آخر من `session_cache.json`.
4. **[DB-CRIT-1] ضرب الاستعلامات المتكرر 3N+1 في `get_all_users_with_castles` (`core/database.py:1690`)**:
   - **السبب الجذري:** استعلام قاعدة البيانات في حلقة تكرارية برمجية لـ 154 مستخدماً، مما يولد 463 استعلاماً في كل طلب.
5. **[STATE-CRIT-1] فقدان تزامن الحفظ عند مغادرة التبويب (`TaskTabContent.tsx:731-743`)**:
   - **السبب الجذري:** دالة تفريغ المكون `useEffect cleanup` تستدعي `updateCastle` مباشرة دون إخطار TanStack Query (`setQueryData`) أو `localStorage`، فيبقى الكاش القديم معروضاً.

### 🟠 أولوية عالية (High - P1)
6. **[PERF-HIGH-1] الحزمة المتضخمة 2.63 ميغابايت لقلاع المستخدمين (`api_server.py:1635`)**:
   - **السبب الجذري:** جلب كافة تفاصيل وإعدادات 663 قلعة في استدعاء واحد بدلاً من نمط Master-Detail.
7. **[DB-HIGH-1] مسح الجداول الكامل (Full Table Scans) بسبب `LOWER()` (`core/database.py`)**:
   - **السبب الجذري:** استدعاء دوال `LOWER(email)` و `LOWER(user_id)` يتجاوز الفهارس العادية في SQLite لغياب فهارس التعبيرات (Expression Indexes).
8. **[NET-HIGH-1] انعدام `AbortController` في كافة استدعاءات `botApi.ts`**:
   - **السبب الجذري:** كتابة دوال `fetch` بدون تمرير `signal`، مما يمنع إلغاء الطلبات عند التنقل.
9. **[NET-HIGH-2] إغراق السيرفر باتصالات السوكيت (1 اتصال لكل بطاقة قلعة)**:
   - **السبب الجذري:** اعتماد `CastleCard` على `useRealBotStatus` الفردي وإهمال هوك `useUserBotStatuses` المجمع.
10. **[SEC-HIGH-1] 10 مسارات داخلية `/api/internal/*` مكشوفة بدون مصادقة**:
    - **السبب الجذري:** مسارات التحكم بالتشغيل والإيقاف الشامل غير محمية بتوكن أمني أو تحقق IP محلي.
11. **[CACHE-HIGH-1] بقاء كاش قلاع المستخدم السابق في التخزين المحلي بعد تسجيل الخروج**:

16. **[INP-MED-1] غياب الـ Debounce عن حقول البحث في الجداول**:
    - **السبب الجذري:** تفعيل الفلترة مع كل ضغطة زر في لوحة المفاتيح مما يسبب تقطيعاً لحظياً (INP degradation).
17. **[i18n-MED-1] نصوص عربية ثابتة في تبويبات إدارة المسؤول (`AdminLayout.tsx`)**:
    - **السبب الجذري:** نصوص غير مربوطة بنظام الترجمة الثلاثي (`ar`, `en`, `tr`).
18. **[THEME-MED-1] ضعف تباين بعض البطاقات في الوضع النهاري (`CastleCard.tsx:543`)**:
    - **السبب الجذري:** استخدام فئات خلفيات بيضاء شفافة غير متوافقة مع الوضع النهاري.

### المرحلة 1: تحسين استعلامات قاعدة البيانات والباك إند (Backend & SQLite Optimization)
- **الملفات المستهدفة:** `core/database.py`, `api_server.py`.
- **التعديلات التفصيلية:**
  1. إنشاء فهارس التعبيرات وحالة الأحرف في SQLite:
     ```sql
     CREATE INDEX IF NOT EXISTS idx_castle_states_lower_email ON castle_states(LOWER(email));
     CREATE INDEX IF NOT EXISTS idx_castle_states_lower_user ON castle_states(LOWER(user_id));
     CREATE INDEX IF NOT EXISTS idx_users_lower_email ON users(LOWER(email));
     ```
  2. إعادة كتابة `get_all_users_with_castles` باستعلام SQL تجميعي واحد بـ `LEFT JOIN`:
     ```sql
     SELECT u.*, 
            COALESCE(c.active_cnt, 0) as active_castles,
            COALESCE(c.pending_cnt, 0) as pending_castles,
            COALESCE(c.total_cnt, 0) as total_castles
     FROM users u
     LEFT JOIN (
         SELECT user_id,
                SUM(CASE WHEN is_active = 1 AND state != 'pending' THEN 1 ELSE 0 END) as active_cnt,
                SUM(CASE WHEN is_active = 0 OR state = 'pending' THEN 1 ELSE 0 END) as pending_cnt,
                COUNT(*) as total_cnt
         FROM castle_states
         GROUP BY user_id
     ) c ON u.uid = c.user_id
     ORDER BY u.created_at DESC;
     ```
  3. نقل استعلامات SQLite المتزامنة داخل الـ WebSocket إلى خيوط منفصلة عبر `asyncio.to_thread`.
- **النتيجة المتوقعة:** انخفاض استعلامات قائمة المستخدمين من 463 إلى 1 استعلام، وتسريع الاستجابة بأكثر من 2.2x فورياً، وحماية الـ event loop من التعليق.

### المرحلة 2: الأمان، العزل التام، وسلامة التعديلات المتزامنة (Security, Concurrency & Isolation)
- **الملفات المستهدفة:** `api_server.py`, `core/database.py`.
- **التعديلات التفصيلية:**
  1. حماية مسار `/api/local/castles/{id}` بـ `Depends(get_current_user)` والتحقق من الملكية، وتجريد حقل `password` تماماً من كائن القلعة المعادة.
  2. تصحيح مسار `/api/castle-data/{email}` بالتحقق الصارم من أن الإيميل المطلوب ينتمي لـ `current_user["uid"]`، ومنع جلب أي بيانات لحساب لا يملكه المستخدم.
  3. تصحيح مسار `/api/bot/start` باستخراج الإيميل المعتمد للقلعة من قاعدة البيانات حصراً بدلاً من الثقة في `req.email`.
  4. حماية كافة مسارات `/api/internal/*` بتوكن داخلي سرّي وتحديد النطاق بـ Localhost فقط.
  5. إضافة حقل `version INTEGER DEFAULT 1` لجدول `castle_states` واستخدام `BEGIN IMMEDIATE` للتحقق من عدم حدوث تعارض حفظ متزامن (Optimistic Concurrency Control).
- **النتيجة المتوقعة:** إغلاق كافة الثغرات الأمنية P0 بنسبة 100%، وحماية التعديلات المتزامنة من فقدان البيانات.

### المرحلة 3: توحيد مصدر الحقيقة في الواجهة وحل نزاع الحالات (Frontend State Architecture)
- **الملفات المستهدفة:** `dashboard/src/components/accounts/CastleCard.tsx`, `dashboard/src/components/accounts/TaskTabContent.tsx`, `dashboard/src/hooks/useCastles.ts`.
- **التعديلات التفصيلية:**
  1. إزالة الحالات المحلية المنفصلة (`liveState`, `connState`) من `CastleCard.tsx`، والاعتماد الحصري على كائن القلعة المحدث في كاش TanStack Query مع دمج تحديثات السوكيت المجمع بسلاسة.
  2. تعديل دورة مغادرة `TaskTabContent.tsx` بحيث تقوم دالة الـ cleanup عند استدعاء الحفظ بتحديث كاش TanStack Query فوراً عبر `qc.setQueryData` وتحديث التخزين المحلي، لضمان عدم ظهور البيانات القديمة عند العودة.
  3. توفير مؤشرات صريحة ومستقلة لحالات التحميل والحفظ والأخطاء والفراغ.
- **النتيجة المتوقعة:** القضاء التام على تجمد البطاقات في الواجهة ومنع ظهور الإعدادات القديمة بعد الحفظ.
