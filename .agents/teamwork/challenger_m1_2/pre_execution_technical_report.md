## 2. المنطق والخطوات التي سيتم تطبيقها (Logic & Planned Steps)

### الخطوة الأولى: إنشاء سكربت الفحص والإجهاد في `tools/`
وفقاً للقاعدة 13 من دستور الوكلاء (`AGENTS_CONSTITUTION.md`)، يُمنع وضع أي سكربت في المجلد الرئيسي أو داخل مجلد الوكلاء، وسيتم إنشاء السكربت حصراً في:
`e:\osmanli\tools\benchmark_m1_stress_suite.py`

يتضمن السكربت:
1. **جناح القياس الإحصائي لـ 500 عينة (500-Iteration Query Benchmark)**:
   - تنفيذ 500 استدعاء متتالي لدالة `core.database.get_all_users_with_castles()`.
   - قياس P50 وP95 وP99 والمتوسط والانحراف المعياري وأقل وأعلى زمن بدقة الميكروثانية باستخدام `time.perf_counter()`.
   - تتبع استهلاك الذاكرة عبر `tracemalloc` (البداية، النهاية، والذروة Peak Memory).
   - التحقق من ثبات عدد المستخدمين وسلامة بنية البيانات المعادة في كل دورة.
2. **جناح اختبار الإجهاد التزامني لحلقة الأحداث (AsyncIO Concurrency Stress Test)**:
   - إطلاق 50 مهمة غير متزامنة (`asyncio.create_task`) تحاكي 50 متصفحاً/عميلاً متزامناً يستعلمون `db.get_user_castles` عبر `asyncio.to_thread` كل 800ms لمدة عدة دورات.
   - تشغيل مراقب نبضات حلقة الأحداث (Event Loop Heartbeat Monitor): حلقة تفحص تأخير `asyncio.sleep(0.005)` كل 5ms. في حال حظر الـ Event Loop بعملية تزامنية متجمدة، سيتجاوز التأخير 20ms أو 50ms.
   - قياس أقصى تأخير للـ Event Loop (Max Event Loop Lag) ومتوسط التأخير تحت ضغط الـ 50 عميلاً.
3. **المقارنة الكمية بخط الأساس في `ROOT_CAUSE_AND_PLAN.md`**:
   - مطابقة النتائج مع خط الأساس (463 استعلام ➔ استعلام واحد، P50 = 20.47ms ➔ المستهدف < 9.5ms، P95 = 23.48ms ➔ المستهدف < 10.5ms).
   - إصدار تقييم نهائي بالأرقام.
